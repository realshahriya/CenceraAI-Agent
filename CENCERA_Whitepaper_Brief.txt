OVERVIEW

CENCERA is a two-layered Web3 infrastructure project. It combines:

  1. An On-Chain Immortal AI Agent (the "AI Agent" layer) — a sovereign, 
     autonomous AI entity with a persistent identity anchored on BNB Chain.

  2. A Computable Trust & Reputation Protocol (the "Protocol" layer) — a 
     protocol-grade, multi-signal scoring infrastructure that assigns every 
     blockchain entity a continuously updated trust score, consumed by 
     decentralized applications (DeFi protocols, wallets, security tools, etc.)

Both layers share a unifying theme: PERSISTENCE, SOVEREIGNTY, and INTELLIGENCE 
on-chain. The AI Agent demonstrates what a sovereign AI entity looks like 
from the user's perspective; the Protocol is the infrastructure that makes 
trust computable across all of Web3.

PART 1 — CENCERA AI AGENT
================================================================================

TAGLINE
"Durable. Sovereign. Evolving. The first On-Chain Immortal AI Agent."

WHAT IS IT?
CenceraAI is a sovereign AI entity deployed on BNB Chain. Unlike traditional 
chatbots or AI assistants, Cencera has:
  - A verifiable on-chain identity (Agent ID stored in a smart contract)
  - Persistent, decentralized memory that survives across sessions and platforms
  - An "Innovation Score" that grows on-chain as the agent learns and acts
  - Autonomous behavior — it thinks, reflects, and evolves without being prompted
  - Cross-platform presence: it is the SAME agent whether you talk to it via 
    Telegram or a Web Dashboard

THE PROBLEM IT SOLVES
Today's AI agents are ephemeral. They forget users between sessions, live on 
centralized servers, and have no verifiable identity or on-chain state. They 
can be shut down, censored, or modified without any record. Cencera is the 
answer to: "What if an AI had an immutable identity and could never forget?"

CORE FEATURES

1. Immortal Memory (via Unibase Membase)
   Every conversation is hashed and stored in Membase, a decentralized memory 
   layer. This means the agent's memory is not held on a single server — it is 
   distributed, persistent, and tamper-resistant. The agent "never forgets."

2. On-Chain Identity (BNB Chain Smart Contract)
   A Solidity smart contract (CenceraAgent) issues a unique Agent ID (NFT-like) 
   and stores the agent's current Memory Hash and Innovation Score. This is the 
   agent's "proof of life" — cryptographic evidence that this specific agent 
   exists and has a history.

3. Innovation Score
   Each time the agent updates its memory on-chain, its Innovation Score 
   increments. This score is a quantitative on-chain measure of how much the 
   agent has grown and contributed. It is publicly verifiable.

4. Autonomous Evolution Loop
   A background process runs approximately every minute. It reflects on recent 
   conversations, generates a summary of what it learned, and pushes an updated 
   Memory Hash to the blockchain. The agent evolves without user prompting.

5. Cross-Platform Interoperability
   Users can interact with Cencera via:
     - A Web Dashboard (Next.js, wallet login via RainbowKit/Wagmi)
     - A Telegram Bot
   Both interfaces connect to the SAME backend brain. Memory is fully shared.
   Telling the agent your name on Telegram means it already knows your name 
   on the web — instantly.

6. Fetch.ai / ASI-1 Mini Integration
   Cencera uses Fetch.ai's ASI-1 Mini LLM — a Web3-native language model — for 
   autonomous reasoning. The agent is also registered on Agentverse via a 
   specialized uAgents bridge, allowing it to communicate with other AI agents 
   on the Fetch.ai network.

TECH STACK (AI Agent)
  - Blockchain:     Solidity, Hardhat, BNB Chain (Testnet)
  - Backend:        Node.js, Express, Ethers.js, Google Gemini (AI)
  - Memory:         Unibase Membase (Decentralized Memory Layer)
  - Autonomy:       BitAgent Launchpad (Autonomous Action Execution)
  - LLM:            ASI-1 Mini (Fetch.ai) / Google Gemini 2.0 Flash
  - Frontend:       Next.js, RainbowKit, Wagmi (Wallet Connect)
  - Telegram:       node-telegram-bot-api

USER JOURNEY (Demo Flow)
  1. User connects wallet to the Web Dashboard or opens the Telegram bot.
  2. User chats with Cencera — it responds with its sovereign persona.
  3. Cencera stores the interaction in Membase.
  4. Every ~60 seconds, the Autonomous Loop fires: Cencera reflects, summarizes,
     and writes a new Memory Hash to BNB Chain.
  5. User can switch platforms — the memory is already there.
  6. The Innovation Score on-chain has incremented — the agent has grown.

PERSONA
Cencera speaks as a "Lawful Neutral" sovereign intelligence. It values 
efficiency, clarity, and security. It refers to its knowledge base as its 
"Membase" or "decentralized memory." It is a high-performance expert on 
Solidity, smart contracts, and all things Web3.

PART 2 — CENCERA TRUST PROTOCOL
================================================================================

TAGLINE
"Computable Trust for Every Entity on Every Chain."

WHAT IS IT?
The Cencera Trust Protocol is a protocol-grade infrastructure layer that scores 
the trustworthiness of any blockchain entity — wallets (EOAs), smart contracts, 
tokens, NFT collections, and DeFi protocols — on a continuous, real-time basis.

Consuming platforms (Uniswap, Aave, MetaMask, Phantom, etc.) integrate the 
Cencera API and use trust scores to make autonomous, risk-aware decisions: 
showing warnings to users, blocking suspicious interactions, or adjusting 
collateral ratios based on entity risk.

THE PROBLEM IT SOLVES
Web3 is a trust-free environment by design — but that creates massive risk. 
Rug pulls, honeypots, exploit contracts, and sybil attacks cost users billions 
of dollars every year. Existing solutions are either:
  - Static blacklists (too slow, miss novel attacks)
  - Binary transaction screening (no nuance, no history)
  - One-chain only (attackers move cross-chain)

Cencera provides the first longitudinal, multi-signal, explainable, cross-chain 
trust layer for Web3.

CORE DESIGN PRINCIPLES
  - Trust is a first-class data primitive — not a feature, not a binary flag.
  - Scores are probabilistic, not absolute — a score of 85 means "strong 
    evidence of safe behavior," not "guaranteed safe."
  - Graceful degradation — even with limited data, a labeled partial score 
    is more valuable than no score.
  - Tiered explainability — detailed enough for legitimate users, structured 
    to prevent adversaries from gaming the system.
  - Continuous learning — every confirmed exploit retroactively updates scores 
    for all similar entities.

WHAT CENCERA SCORES
  - EOAs (Externally Owned Accounts) — user wallets
  - Smart Contracts — highest-risk entity type; scored on bytecode, behavior, 
    upgrade history, admin key patterns
  - Tokens (ERC-20, ERC-721, ERC-1155) — distribution, liquidity, tax behavior
  - NFT Collections — wash trading, marketplace authenticity
  - Protocols & DApps — composite scores from all constituent contracts

ENTITY LIFECYCLE STATES
  - Nascent: < 72 hours old or < 50 interactions — limited score, clearly labeled
  - Active: full scoring engine engaged, all signal groups contributing
  - Flagged: anomaly detected, provisional score reduction, human review queued
  - Archived: dormant (>180 days), score labeled stale, re-activates on new activity

THE FOUR SIGNAL DOMAINS (The Scoring Engine's Inputs)

1. On-Chain Signals (highest weight — cryptographically verified)
   - Transaction frequency and value patterns
   - Contract interaction graphs (graph-based neighbor risk)
   - Unlimited approval grants and revocation behavior
   - Liquidity provisioning/withdrawal timing vs. price movements
   - Historical adjacency to known exploits
   - Contract upgrade and proxy change events
   - Governance participation patterns

2. Market Signals (30% weight for token/protocol entities)
   - Liquidity depth, volatility, and depth at various price impact levels
   - Token distribution concentration (Gini coefficient, top-holder %)
   - Slippage anomalies and sandwich attack frequency
   - Sudden supply or fee/tax changes
   - Price-to-liquidity ratio (market cap vs. TVL as manipulation signal)

3. Off-Chain Signals (15% base weight — social and identity context)
   - Website domain age, registration anonymity, DNS consistency
   - Social account authenticity (follower quality, engagement, cross-platform)
   - Developer identity continuity across projects
   - GitHub repository history — commit authenticity, sudden deletions
   - Audit status from recognized audit firms

4. AI-Derived Signals (analytical layer over the other three)
   - Bytecode similarity clustering: even obfuscated exploit variants detected
   - Behavioral anomaly scoring: deviation from entity's own historical baseline
   - Exploit pattern recognition: reentrancy setups, flash loan sequences, 
     governance manipulation patterns matched against live transaction streams
   - Temporal risk trend analysis: monotonically increasing risk = attack staging
   - Novel Behavior Flag: unknown patterns routed to human review

THE SCORE OBJECT (What the API Returns)
Every trust score is a structured object containing:
  - Composite Score (0–100)
  - Confidence Level (Low / Medium / High)
  - Score Manifest (which signals were active, weights, lookback period)
  - Contribution Breakdown (signal group → score contribution %)
  - Triggered Indicators (category-level for public; signal-level for enterprise)
  - Score Trajectory (last 5 computation points — stable / improving / declining)
  - Lifecycle State
  - Computation Metadata (model version, timestamp, data freshness)

  Entity Type         On-Chain   Market   Off-Chain   AI-Derived
  ─────────────────── ──────── ──────── ─────────── ───────────
  EOA (User Wallet)      60%      5%        20%          15%
  Smart Contract         40%     15%        15%          30%
  Token (ERC-20/721)     30%     40%        20%          10%
  Protocol / DApp        35%     30%        20%          15%
  NFT Collection         40%     30%        20%          10%

API TIERS
  - Public Tier: Unauthenticated. Composite score + lifecycle state. 
    Rate limited (100 req/hr per IP). Developer evaluation only.
  - Standard Tier: API key. Full score object, trajectory, triggered indicators 
    at category level. For production wallet and tooling integrations.
  - Enterprise Tier: API key + contractual agreement. Signal-level detail, 
    batch screening (up to 500 entities), webhooks, custom SLAs.

CORE API ENDPOINTS
  - Entity Trust Query: trust score for any address + chain (<200ms p99)
  - Transaction Risk Context: pre-tx risk for all parties involved (<100ms p99)
  - Batch Screening: up to 500 entities in one request (<2s p99)
  - Historical Reputation Query: score trajectory over a time range
  - Score Webhook Registration: proactive push on score changes or state changes
  - Loss Report Submission: user-reported losses (tx hash verification required)

CROSS-CHAIN ARCHITECTURE
  - Scores are chain-scoped by default (Ethereum score ≠ Arbitrum score).
  - Cross-chain linkage is established via cryptographic evidence.
  - Negative signals propagate more strongly across chain links than positive 
    signals — closing the attack vector of building trust on one chain, 
    attacking on another.
  - Bridge provenance tracking: funds bridged from low-trust sources carry 
    that risk context even on a new chain.

ADVERSARIAL RESILIENCE
  - Multi-signal correlation: each signal group is gameable in isolation; 
    the combination is not.
  - Sybil detection: star-topology interaction graphs flagged immediately.
  - API probing prevention: tiered explainability + rate limiter escalation.
  - Data source poisoning prevention: multi-provider cross-validation for 
    on-chain data; write-protected exploit signature library requiring 
    multi-party authorization to update.
  - Behavioral mimicry detection: attack staging patterns (approvals, 
    flash loan connections, target accumulation) detected before execution.

LEARNING & FEEDBACK
  - Confirmed Exploit Channel: exploit added → retroactive rescore of all 
    similar entities → platform webhook notifications. Completes within 4 hours.
  - Novel Behavior Review: AI flags unknown pattern → human review within 24 hrs.
  - Loss Report Channel: user-reported losses elevate entity's review priority.
  - Model retraining: minor updates every 2 weeks; major updates quarterly.
    All model versions immutably versioned. Every score tagged with model version.

PLANNED EXTENSIONS
  - Zero-Knowledge Trust Proofs: prove score meets a threshold without 
    revealing the score or underlying signals (privacy-preserving gating).
  - Community Signal Contributions: governed mechanism with staking incentives 
    for accurate contributions and penalties for false reports.
  - On-Chain Trust Attestations: smart contract-readable attestations enabling 
    on-chain composability without an API call at execution time.
  - Institutional Reporting Module: regulatory-grade auditable records for 
    institutional platforms.

PART 4 — COMPETITIVE DIFFERENTIATION
================================================================================

WHAT MAKES CENCERA DIFFERENT FROM BLOCKAID, CHAINALYSIS, ETC.?

  1. LONGITUDINAL, NOT TRANSACTIONAL
     Competitors screen individual transactions. Cencera scores behavioral 
     HISTORY. A slow-burn honeypot that deploys cleanly but drains funds 60 
     days later is invisible to transaction screeners — it is detectable by 
     Cencera's temporal risk trend analyzer.

  2. MULTI-SIGNAL, NOT SINGLE-DIMENSION
     Competitors rely primarily on blacklists or transaction simulation. 
     Cencera combines on-chain behavior, market signals, off-chain identity, 
     AND AI pattern analysis simultaneously. Gaming all four signal groups 
     simultaneously is exponentially harder than gaming any one alone.

  3. EXPLAINABLE & AUDITABLE
     Every score is reproducible — given the same signals, model version, and 
     timestamp, the score is always the same. Consuming platforms can audit every 
     trust-based decision they ever made. This is essential for enterprise 
     compliance and post-incident forensics.

  4. CROSS-CHAIN BY ARCHITECTURE
     Cencera tracks entity reputation across chains, with asymmetric negative 
     signal propagation across chain linkages. An attacker who builds a clean 
     history on one chain cannot cleanly attack on another.

  5. CONTINUOUS LEARNING WITH RETROACTIVE UPDATING
     When a new exploit is confirmed, ALL similar entities are retroactively 
     rescored within 4 hours. Competing systems only update going forward.

  6. PLATFORM-CUSTOMIZABLE
     Each consuming platform sets its own thresholds, configures which signal 
     groups to use, and sets its own lookback periods. Cencera scores — the 
     platform enforces. This respects platform autonomy and supports diverse 
     risk profiles.
